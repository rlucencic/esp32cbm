# C128 CP/M boot and 1571 activity, 2026-11-24

Use the PAL C128 and its 1571 at device 8 with the 28 May 1987 CP/M 3.0
boot disk. The unpacked `28may87-1.d64` has SHA-256
`fdde8de25afd91c8acab0bcbe4d6ad13572a6f97c68f3b8638e5f84491735ec7`.
[CP/M archive and disk notes](https://www.zimmers.net/anonftp/pub/cpm/sys/c128/system/index.html)

## Reproduce the measurements

Build an instrumented host executable in a separate output directory.
The firmware exposes the same counters via an opt-in CMake definition.

```sh
make -C components/cbm/host BUILD=build/drive-metrics CBM_DRIVE_METRICS=1
CBM_ROMS="$PWD/roms" CBM_DISK8=/path/to/28may87-1.d64 CBM_STATUS=50 \
  components/cbm/host/build/drive-metrics/cbm_host c128 1500
idf.py -B build -DCBM_DRIVE_METRICS=ON build
```

Set the CMake option back to `OFF` for a regular firmware build. The
metrics log blocks of 50 guest frames per active 1571. A warm reset starts
a new count within the current block. `gcr` counts
byte times under the head, including sync, `ready` counts non-sync
bytes delivered to VIA2, `so` counts assertions to the drive CPU and
`so_2mhz` is the subset at 2 MHz. `burst_tx` counts bytes sent from
the 1571's CIA to the C128. A logical sector request can generate many
of these events. The counters and logging compile out by default.

## Host results

The first matching `A>` capture was at frame 1360 with snapshots every
ten frames (27.2 seconds of guest time). During frames 1–1350, drive 8
processed 996,891 GCR byte times, delivered 976,091 non-sync bytes
and asserted SO 399,674 times. Of those assertions, 399,358 (99.9%)
were at 2 MHz. The drive sent 35,770 burst bytes. The busiest measured
50-frame interval had 26,607 assertions at 2 MHz.

The instrumented and stock host replays matched the frame and
instruction logs, all 51 ten-frame captures from frame 1250 through
frame 1750, the `DIR` capture and the final image. The disk was unchanged
in both runs.

## MaTouch results

Both builds used ESP-IDF 5.5.6 on the MaTouch with the speaker enabled
to put the console on UART. The debugger sampled the guest banner and
`A>` prompt roughly every 1.4 seconds after a cold C128 start.

| Build | First prompt observed | Median FPS during the disk-heavy window | Sample range |
| --- | ---: | ---: | ---: |
| Stock | 35.36 s | 39 | 36–45 fps |
| Drive metrics | 35.37 s | 40 | 37–46 fps |

The rate window is 12–32.7 seconds after restarting as a C128. The prompt
observations agree within the polling interval. A single paired boot
measures the approximate diagnostic cost.

The 27 sets of drive 8 counters through frame 1350 matched the host
exactly, including all 35,770 transmitted burst bytes. The board captures
of the prompt and the CP/M `DIR` listing matched byte for byte across the
stock and instrumented builds. Both runs left the mounted image unchanged.
